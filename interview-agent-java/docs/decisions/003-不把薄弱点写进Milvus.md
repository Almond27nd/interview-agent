# ADR-003：不把薄弱点写进 Milvus

> **状态**：已决策，勿改回去
> **日期**：M3 落地期间
> **关联**：`memory/MemoryRecallService.java`

## 背景

三路混合召回里有一个语义通道（embedding 余弦相似度）。
自然想到的做法是把薄弱点写进 Milvus 向量库，用现有的向量检索能力。

## 决策

**不写进 Milvus。用一次批量 embedding + 内存点积代替。**

## 理由

**并非所有语义检索都需要向量库。**

单用户候选薄弱点只有 10 条量级、JD 技能十几个，是「十几 × 十几」的相似度矩阵——
一次批量 embedding + 内存点积即可，微秒级。

写进 Milvus 有三个实际代价：
1. 额外 collection 与 schema 维护
2. 写入/删除的一致性问题（薄弱点会频繁变更）
3. "为 100 个向量搭一套向量库"的复杂度失衡

## 核心原则

**复杂度要和问题规模匹配。** 为 100 个向量维护一套向量库基础设施，
是"手里有锤子看什么都像钉子"的典型表现。
