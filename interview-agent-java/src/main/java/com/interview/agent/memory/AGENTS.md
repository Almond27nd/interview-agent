# memory 包约束

## 阈值红线

- **`MemoryWriteGate.MERGE_THRESHOLD = 0.75`**
  调低会误并 `MySQL索引` 与 `MySQL事务`（实测 Jaccard = 0.50）。
  误并使知识点**永久失去独立追踪能力**，代价远高于漏并（漏并只是多占一个名额）。
  topic 只有 2~8 字，短文本 bigram 天然偏高，阈值必须取高。

- **`MemoryRecallService.SEMANTIC_THRESHOLD = 0.42`**（换 embedding 模型必须重跑校准）
  实测"相关"与"无关"的余弦区间严重重叠（0.35~0.56 vs 0.32~0.40），不存在干净切分点。
  语义分值即使低于阈值仍作为一路排名参与 RRF，只是不单独触发"强相关"标记。

- **`LongTermMemory.WEAK_POINT_CANDIDATE_POOL = 30`** 必须大于 **`MemoryRecallService.FUSE_TOP_K = 10`**
  这是 M4 层次修正的全部价值。两者相等则 RRF 退化为 N 进 N，只重排不筛选。
  此不变量由 `HarnessInvariantsTest` 守护。

## 禁止的操作

1. **禁止**因"某领域评估指标偏低"而把该领域评估样本的词抄进同义词表
   - 历史事故：曾这样做使 Recall@3 从 0.6194 飙到 0.8083，实测泄漏率 53.8%，已全部回滚
   - 三个反常信号：反自证"均失败"骤降 / 语义贡献由正转负 / 某分组跳满分
   - 规则型组件天生容易泄漏——"加一条规则"和"记住一个答案"在实现上是同一个动作
   - 泄漏率由 `LeakageReport` 持续度量，测试卡 `leakRate <= 0.60`

2. **禁止**物理删除 WeakPoint
   - 达标只打 `masteredAt` 软失效标记
   - 物理删除会使"复发检测"在结构上不可能实现（删除后再错只被当全新薄弱点）

3. **禁止**把薄弱点写进 Milvus（见 ADR-003）
   - 单用户候选 10 条量级，是"十几 × 十几"的矩阵，一次批量 embedding + 内存点积即微秒级
   - 写进 Milvus 付 collection/schema 维护 + 频繁变更一致性 + 复杂度失衡三份代价

## 已知取舍（不是 bug，勿"修复"）

- **`stubborn` 单调不减，无复位逻辑**
  语义是"历史上曾长期卡住"这个事实不因近期答好而抹掉，`+0.35` 会一直加着。
  被追问时如实承认，不要硬编成"有复位逻辑"。

- **`relevant` 为 0 时不做兜底**
  真转岗时"一条都不相关"是正确结论，硬塞反而误导 LLM。只告警不补救。

- **`priority()` 四个权重系数（0.35/0.15/0.3/0.2）纯经验拍定，无调参实验**
  能说清的是结构性约束：主信号独占 1.0，三个修正项各自封顶且和为 0.85 < 1.0。
  要真调需要在线实验（不同权重下出题 → 看后续答题提升），离线数据集给不了。
  **别硬编成"实验调出来的"，一追问实验设计就崩。**

- **三路 Precision（0.6486）低于两路（0.6639）**
  语义通道提高召回的同时引入了误召回。这是如实记录的取舍，不是笔误。

## 同义词表的三个使用场景（同一套函数，三处复用）

1. **写入侧**：`MemoryWriteGate.canonicalize` — 实体归一
2. **召回侧**：`MemoryRecallService.lexicalScore` — 词法通道打分
3. **方向去重**：`DirectionQuotaChecker.dedup` — Phase 1 方向去重

三处都传**空集合**给 `canonicalize` 的第二参数（只要同义词表映射，不要 bigram 近似合并）。
